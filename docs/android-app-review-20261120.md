# Androidアプリ 全画面レビューと改修（2026-11-20）

対象: `android/`（ブランチ `feat/android-app`）。全10画面とアプリ設定・ナンバー通知を、実機NP1のAPIデータ（ADB転送とTailscale経由）を使ってエミュレータ（Pixel相当 1080×2400 / Echo Show 5相当 960×480dp、ライト・ダーク）で確認した。本体の設定を変える操作（保存・適用・サービス操作・フォーマット等）はテストで実行していない。

## 見つかった不具合（修正済み）

| 画面 | 内容 | 原因 |
|---|---|---|
| 全体の地図 | 地図が表示されない（灰色の格子のみ） | 地図タイルを使わない自前Canvasだった。MapLibre Native＋Web UIと同じOpenFreeMapスタイルに置換 |
| ダッシュボード | 走行距離が出ないことがある | `/trips` の取得失敗を握りつぶし再試行なし。30秒ごとに更新し、失敗時は再試行ボタンを表示 |
| ダッシュボード | 「24時間」で何も出ない | APIの `hours[].from/to/observed` を `start/end` として読んでいた |
| ダッシュボード | Wi-Fiが常に「未接続」 | summaryの `wpa_state`/`ip_address` を `state`/`ipv4` として読んでいた |
| ダッシュボード | 現在地が測位中以外は出ない | `/device/gps/live` と最後の位置・24時間の軌跡（Web UIと同じ）を使用 |
| 4G・システム | 月間上限やテーマ保存で他の設定（地図の色など）が消える | `/settings` を一部項目だけで組み立てて PUT していた。サーバーの値を読み直し、変更項目だけ差し替える `updateSettings` に統一 |
| 4G | APN適用の結果を確認しない／WAN IP・設定APNが「未取得」 | 適用ジョブの追跡・保存済みプロファイル表示・インターフェースからのWAN IP取得をWeb UIと同様に実装 |
| 走行履歴 | 電波マップが一度も表示されない | `/radio/history` は `gps.lat/lon` とエリア集計 `cells` を返すのに、平坦な `lat/lon` を期待していた |
| ライブ | 最大1fpsのJPEGのみ（Web UIはH.264動画） | WebView上でWeb UIと同じWebRTC（H.264）を実装。JPEGは切り替え可能 |
| ドラレコ再生 | 再生が不安定 | プレイヤーの破棄処理のキーが毎回変わるラムダで、再描画のたびにプレイヤーが解放されていた |
| 純正設定 | 操作・診断のボタンが全て無効 | API項目（`readOnly`/`inputs`/`unavailableReason`）とモデルが不一致。入力・確認ダイアログ、取付調整中の接続維持（7秒ごと）を移植 |
| 純正設定 | 「取付高さ 2147483649」など無効値をそのまま表示 | 0x80000000以上は「未設定」と表示（Web UIと同じ） |
| システム | 純正サービスの停止・再起動が確認なしで1タップ実行 | 一覧＋詳細に整理し、影響を示す確認ダイアログを追加 |
| 共通 | エラーが「409: …」のようにコード付き／一時的な遅延で「未接続」 | サーバーの日本語の理由をそのまま表示。通信失敗時は接続確認してから未接続と判定し、接続判定のタイムアウトを延長・再試行 |

## UI・文言

- デザイントークン（`Spacing`: 画面端16dp・カード内16dp・カード間12dp）を共通化。カード見出しの説明文と右端のアイコンを本文と同じ線に揃えた（`PanelAction`）。
- ダッシュボード: オーナーがWeb UIで選んだ構成（地図を全面背景、スマホは右上に前方カメラと下から引き出すシート、横長は左にカード列）。地図表示⇔詳細表示はバーのアイコンで切替。
- スマホ下部メニューは「ダッシュボード・ネットワーク・ドラレコ・設定」（「ホーム」はオーナーが不採用）。
- 開発者向けの表記（`MOBILE NETWORK`、`rev.1`、`/proc/meminfo` の生表示、英語の状態値、`OTA抑止` 等）を利用者向けの日本語に置換。
- スクロールするページ内の地図は「タップして地図を操作」方式にし、ページのスクロールを妨げない。

## 残課題・注意

- **tripStats の不一致（バックエンド）**: `/system/summary` の `tripStats` はSDに残る測位だけから集計しており、7日でも17.8 kmなど `/trips`（185.8 km）より少ない。Web UIは `/trips` 取得前の暫定表示に使っているため一瞬誤った値が出る。アプリでは使わないようにした。バックエンド側で揃えるか、Web UIでも暫定表示をやめる検討が必要。
- **H.264ライブ**: WebRTC接続と再生開始（1920×1080・26fps）までは確認したが、エミュレータのデコーダーが追いつかず映像は黒いまま。実機スマートフォン／Echo Show 5での表示確認が必要。
- NP1の負荷が高い時（load 9〜11）は起動から全データ表示まで20秒程度かかることがある。
- 録画原本はAndroidのダウンロード機能で「ダウンロード/NP1」に保存する。

## 確認手順（再現用）

```powershell
cd android
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "K:\Android"
.\gradlew.bat testDebugUnitTest assembleDebug
```

- 地図スタイルはWeb UIの定義から生成: `node tools/android-map-styles.mjs`（`android/app/src/main/assets/map/*.json`）。
- エミュレータからは `adb forward tcp:18080 tcp:80`（実機）＋ `http://10.0.2.2:18080`、またはPCがtailnetにいればTailscaleアドレスで接続できる。
