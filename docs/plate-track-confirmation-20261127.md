# 追跡OCRの確定条件（2026年11月27日・開発候補）

短いトラックの終了時に一連番号が競合しているとき、小さい枠で得た読みと、後から得た大きな枠の読みを再比較する。大きな枠の主OCR（0.90以上）、照合OCR（0.85以上）、桁位置OCR（0.85以上）と系列出力（0.97以上）が同じ4桁を支持し、先行候補との差が1桁で、先行候補に強い別読みがない場合に採用する。小さい枠の幅は採用枠の80%以下とする。支持回数は1回のまま保存処理に渡すため、単発確定を無効にする設定やユーザーのしきい値が適用される。

もう一方の変更は、同じ位置で3秒以上離れた2画像の一連番号が一致する従来の条件に対するもの。幅35〜39 pxの枠で、後の画像に十分な数字エッジ（0.30以上）があり、主OCRと照合OCRがともに0.81以上、系列出力も0.99以上で一致した場合に限り、同じ番号を支持する桁位置OCRの下限を0.82から0.75へ変更する。

開発用28再生条件、延べ1,488フレームで旧版と比較した。保存件数は45件から46件。新規の1件は原映像で正解が確認された夜間の車両だった。既存45件は生成IDを除いて全保存項目が一致した。映像や正解が重なる6 fps・8 fpsの再生、二車両を重ねた対照試験を含む。28条件は独立した28車両を意味しない。

再利用するのは追跡処理がすでに保持しているOCR結果と画像特徴。追加のカメラ取得やモデル推論は行わない。

## 追跡統合後の画像と通過中の連続読み

同じ車両に対応すると確認済みの追跡を統合するとき、前後の観測について元の時刻、フレームID、枠、OCR結果、確度設定を一緒に引き継ぐ。同じ時刻の別枠や同一IDの再利用は1画像として扱い、直近64画像までを時刻順に保持する。冒頭にOCR未実行の枠を含む車両も、実際に読めた画像で短時間の競合を判定できる。

通過中に斜めのプレートを読む場合は、番号を採用する根拠を別の露出からも集める。異なる3時刻で数字輪郭を確認でき、主OCR、数字照合、系列出力の3つが4桁すべて一致し、画像内で同じ向きに移動したときに、既存の代表画像・支持回数を使って確定する。確認できた異番号の強い証拠がある場合はこの経路を使わない。追加の推論は行わない。

初回候補と追加版を開発専用の昼夜54条件・延べ3,070フレームで比較した。保存が84件から85件となり、昼間の8 fpsで原画確認済みの通過車両を1件追加できた。6 fpsの新規登録は0件。既存84件は生成IDを除く保存項目が一致した。フレームの順序、重複、履歴上限、3画像の時刻・向き、競合、利用者の最少支持回数と確度設定は単体テストでも確認した。
