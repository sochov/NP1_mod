# 中断したナンバープレートの登録を引き継ぐ

センサーは画像ごとの枠・読み・投票から追跡IDを発行する。登録ストアでは、別の追跡IDで再登場した車について、確定済みの一連番号、検出区間、代表枠、付帯項目から直前の記録を引き継ぐ。新規登録時と追跡の更新時に判定し、成立した関連を更新行に保存する。履歴の初回表示や旧ファイルの読込みは過去の記録を再分類しない。

- 最長150秒の空白を許容する。直前まで前方に一定時間いたか、枠の高さ・大きさ・横移動が再出現までの時間と両立するかを検査する。3桁は時間・位置をさらに絞る。
- 2〜3桁の短番号を別の角度から捉えた場合、12秒以内に同じ側・同じ高さの車列から異なる4桁番号の車を2台観測し、少なくとも1台の追跡区間が空白前後を結んでいれば再結合の候補にする。
- 検出区間の重なり、複数の接続先、異なる確定済み付帯項目があれば別々に保持する。観測数はフレーム数であり、独立OCR回数には換算しない。一連番号の登録可否は従来どおりセンサーと登録条件で決まる。
- 元の追跡ごとに最新スナップショットを保持する。累積検出数の更新や再送による二重加算を防ぐ。統合後の表示は最初の検出から最後までとし、採用済みの地名・分類番号・ひらがなを補完する。後で番号の訂正や強い矛盾が判明すれば原記録単位に分離できる。
- 地図、通知、一覧、共有は同じ統合IDと区間を参照する。代表画像のファイルIDには実際に画像を取得できた元の追跡IDを使う。共有キューに残る初回送信前の自動登録は、統合成立時に子IDを取り除く。送信中、送信試行済み、利用者が明示的に送信したイベントの履歴を保持する。
- 日付をまたぐ場合は最初に観測した日に集計する。Webプロセス再起動時は当日と前日の稼働中の記録を復元する。紐付け先が保存期間経過などで失われた元記録は単独で表示する。

検証は `go test ./internal/plate ./internal/numbershare ./internal/api`。同じ一連番号の並走、後続更新で初めて確度が上がる例、付帯項目の後日訂正、15分後の再遭遇、タイムアウト、午前0時をまたぐ再起動、保存失敗と再送、未送信・送信中の共有を含む。実機記録と映像を用いた個別判定は管理対象外の評価資料に保存する。
