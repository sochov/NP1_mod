# Androidアプリ 横画面ダッシュボード（2026-11-21）

オーナー指示: 横画面用の新しいダッシュボード。地図を全画面に出し、メニューバーやタイトルは出さない（左下に小さくメニューボタン）。画面を区切り、右側の上は前方カメラ、下は直近のナンバー検知履歴をリアルタイムに表示・更新する。条件一致ナンバーのポップアップはそのまま。横画面で起動したら自動でこの画面にする。抜けた後は通常のアプリ画面。あわせて、横画面の通常画面ではナビゲーションレール上部のNマークを外す。

## 仕様

| 項目 | 内容 |
|---|---|
| 表示条件 | 起動時に横画面なら `landscape` ページで開始（`rememberSaveable` の初期値）。縦に回すと通常のダッシュボードを表示し、横に戻すと再びこの画面 |
| 全画面 | 表示中はステータスバー・ナビゲーションバーを隠す（端からスワイプで一時表示）。他の画面へ移ると戻す |
| 地図（左） | 現在地を追従（ズーム15.5）、24時間の軌跡。動かすと追従を止め、右下の現在地ボタンで戻す。測位できない時・接続できない時だけ左上に注意を表示 |
| 右側の幅 | 画面幅の36%（300〜460dp）。Echo Show 5（960dp）で約346dp |
| 前方カメラ | 右列の幅いっぱいに余白なしで表示（16:9）。JPEG静止画を1秒ごと（前方のみ。通常ダッシュボードの2カメラ×2秒と同程度の負荷）。左上に録画状態（分かる時だけ）とナンバー認識の状態を並べる |
| ナンバー履歴 | `/plate/records?from=昨日&to=今日&limit=40` を1.5秒ごと。ポップアップの通知設定とは独立して常に更新。初回取得分は強調せず、以後の新着・条件一致が増えた記録を4秒強調。条件一致は橙、NumberShareの危険は赤。行を押すとナンバー画面のその記録へ |
| 認識状態 | `/plate/status` を15秒ごと。認識中／ナンバー記録停止中／認識プロセス未起動などをカメラ上の録画状態の隣に表示。履歴は見出しを置かず、カメラの下を全部使う。新着が先頭に入った時は、一覧を下へスクロールしていなければ先頭へ戻す |
| メニュー | 左下の丸ボタン。接続状態、ナンバー通知の種類、全画面（ダッシュボード〜システム、最後にアプリ設定）。選ぶと通常の画面へ移る |
| ポップアップ | 既存の `PlatePopupOverlay` をそのまま使い、地図の上（右側の列を避けた位置）に表示 |
| 戻り方 | 通常のダッシュボードを横画面で開いているとき、バーの全画面ボタンでこの画面へ。戻るキーはこの画面ではアプリ終了（ホーム扱い） |

アプリ設定: 特別扱いをやめ、ナビゲーションの最後の項目「アプリ設定」とした（左レールの最下段、スマホの「設定」グループの最後、横画面ダッシュボードのメニューの最後）。選ぶと従来どおりアプリ設定のダイアログを開く。

ナンバーのプレート表示: 文字サイズをバッジの大きさ（dp）から決め、端末の文字サイズ設定やフォントの上下余白で番号が枠からはみ出さないようにした（一覧の小さいバッジで番号が切れていた）。

ナビゲーションレール: Nマークを削除し、小型（Echo Show 5など）では項目の余白とアイコンを詰めて、960×480dpで全11項目（アプリ設定を含む）が収まるようにした（スマホ横の高さ411dpではスクロール）。レールの下端と、通常のダッシュボードを横画面で表示した時の右下の位置表示は、ジェスチャーナビの領域（操作できないハンドル部分）を空けず、3ボタンナビなどタップできるバーがある時だけ避ける（`WindowInsets.tappableElement`）。

## 確認

- 単体テスト: `LandscapeDashboardTest`（初回は強調しない／新着と条件一致の追加を強調し1分で忘れる／右列の幅）。全18件成功。
- エミュレータ（実機NP1のデータ、Tailscale経由）: スマホ横（914×411dp）とEcho Show 5相当（960×480dp）で、横画面起動→全画面表示、地図・軌跡・前方カメラ・録画中表示・認識中表示・ナンバー履歴、メニュー→通常画面、全画面ボタンで復帰、テスト用ポップアップの位置を確認。縦画面起動は従来のダッシュボード。
- 走行中の新着検知は屋内のため未確認（ロジックは単体テストで確認）。テスト用ポップアップはアプリ内だけのもので、履歴には追加されない（サーバーの記録だけを表示）。
