# ブラウザ画面と前面LEDの連動

システムのLED / 音声にある「画面連動」から、PCの画面・ウィンドウ・ブラウザタブを選びます。ブラウザ標準の共有選択画面を使い、開始ボタンを押すまで画面取得は行いません。対応ブラウザとHTTPSまたはlocalhostが必要です。LANのHTTPではHTTPSへのリンクと利用条件を表示します。モバイルはブラウザ自体の画面共有対応に依存します。

共有画面のプレビュー上で横長の範囲をドラッグまたはタッチ操作で選び、選択枠を移動・右下をリサイズできます。位置・幅・高さの数値調整も可能です。範囲を横に5分割し、各区画に重なる**全画素の面積加重平均**を求めます。単一の代表画素ではありません。画面全体は処理負荷を抑えるため最大640×360に縮小し、その画像から平均します。小数の境界も重なり面積で重み付けします。

彩度・明るさ・コントラスト・左右反転を適用し、経過時間ベースの指数平滑化を加えます。計算はブラウザ内で完結し、本体へ送るのは0〜255の整数RGB値5組と連番だけです。画像・映像・選択画面名はサーバーへ送信しません。約10fpsを上限とし、送信中の次フレームは最新の1件だけ保持します。

UIの初期値は軽い強調として彩度125%・明るさ110%・コントラスト115%です。各sliderで100%へ戻せます。範囲のリセットは範囲だけを戻し、色の調整値を変えません。面積平均のalgorithm自体を変更したものではありません。

## API契約

- `POST /api/v1/device/led/screen/sessions` → `{id, frameIntervalMs:100, idleTimeoutMs:1500}`
- `PUT /api/v1/device/led/screen/sessions/{id}` ← `{sequence, zones:[[R,G,B],…5組]}` → `{accepted:true, sequence}`
- `DELETE /api/v1/device/led/screen/sessions/{id}`: 通常の保存済みLED設定に戻す

停止、共有トラック終了、画面遷移、pagehide、送信失敗でキャプチャトラックを停止し、セッション削除を試みます。pagehideの削除はfetch keepaliveを使用します。他のウィンドウやタブで映像を再生する用途のため、visibilityがhiddenになっただけでは停止しません。ブラウザやOSによるバックグラウンド処理の抑制は別途実ブラウザ確認が必要です。通信喪失時に削除が届かないケースは、本体側の無更新タイムアウトで復帰する必要があります。開始時のAPI待機は最大5秒、フレーム送信は最大1秒です。送信結果を確認できない場合、成功扱いで続行しません。

## 本体の一時セッション

brokerの`led.ScreenStore`が32byte乱数のセッションIDをメモリ内だけで管理します。同時に有効なセッションは1件です。5RGB・連番・更新時刻・有効期限だけを`/run/np1-control/led-screen.json`へ原子的に書き込み、画面画像・IDはファイルに含めません。0600の通常ファイルを要求し、ファイル・祖先ディレクトリのsymlinkを拒否します。Linux実機では同じUIDが所有するファイルのみ読み込みます。broker再起動時はセッションを破棄し、RAM上のファイルも削除します。保存済みのLED設定・起動設定は変更しません。

RGBは厳密に5×3の整数0〜255です。不足・過剰の配列、null、小数、重複key、未知key、余分なJSONを拒否します。連番は正のJS safe integerかつ単調増加で、再送や古い連番ではTTLを延長しません。フレーム間隔は100ms以上で、早着した1件だけを次の送信時刻まで最大100ms待機させ、2件目の待機は拒否します。これによりブラウザのタイマーやネットワークの小さな揺れを偽のエラーにしません。DELETE/Resetは待機も解除します。

workerは100msごとに`ReadScreenFrame(ScreenFramePath, now)`を読み、有効なら5RGBを優先します。ファイル削除、期限切れ、不正ファイル、時計の巻き戻りで未来のフレームとなった場合は通常設定へ戻します。通常LED設定への有効な変更時は`DefaultScreenStore.Reset()`でセッションを終了します。APIのacceptedはRAMキューの受理を表し、実際の点灯色の光学的なread-backではありません。監査ログへ記録するのは開始・終了のみで、毎フレームやIDを永続記録しません。

## 共有音声をNP1で再生

「音声もNP1で再生」は初期OFFです。有効にした場合だけ、画面選択時にブラウザへaudio:trueを渡します。マイクは取得しません。ブラウザの共有画面で音声共有を選ぶ必要があり、OS・ブラウザ・共有対象によって音声トラックの有無が異なります。音声トラックを取得できない場合は理由を表示し、LEDだけ継続します。

AudioContextは開始ボタンの操作中に準備し、同一Originの静的AudioWorkletを読み込みます。Workletは左右チャンネルを平均してmonoへ変換し、サンプル面積を重み付けして24kHzへ変換します。200msごとに9600byte（4800sample）のPCM16LEを作り、`POST /api/v1/device/audio/sessions`で取得したセッションへ`PUT {sequence,pcm:base64}`で送ります。Workletはローカルへ無音を出力するため、プレビューから二重再生しません。data:やblob:のWorkletは使わず、CSPのscript-src selfで読み込める独立したassetsファイルにします。

音声の送信も1件だけ実行し、遅延時は最新の200msだけ保持します。再送後の瞬間的な詰め込みを避けるため応答後50ms以上空けます。音声の通信エラー・変換エラーでは音声だけを停止し、LEDを維持します。共有終了・ページ離脱・全体停止では両方を終了し、音声のDELETEもkeepaliveで試行します。本体の2秒無更新watchdogはブラウザ側から独立しています。

## ホスト検証

`frontend/tests/screen-colors.spec.ts` は合成画素で面積平均、分数境界、色補正、反転、時間平滑を検証します。`frontend/tests/screen-led.spec.ts` は合成canvasのcaptureStreamとgetDisplayMediaのモックを使い、実デスクトップを取得せずブラウザ動作を検証します。13件PASS。RGBのみの送信、単一送信・最新優先、キャンセルと再試行、通信エラーとタイムアウト、hidden継続、共有終了、pagehide、画面遷移、mouse/touch選択、HTTPS案内を確認しています。390pxのライト・ダークとデスクトップの画像を確認し、既存フォームのflexに起因する色見本やsliderの縮み、更新中の数値入力の巻き戻りを修正しています。実機LEDの色・復帰・サービス共存は別途実機試験が必要です。

音声追加後は合成oscillatorをMediaStreamに追加し、実AudioWorkletでCSP self下のstatic asset読込・PCM生成とAPI送信・終了を確認しています。48kHzからのdownmixとLE形式、44.1kHzの分数レートで処理ブロックを跨ぐ連続性、振幅clamp、無音も検証し、RGBと音声の関連19件PASSです。実音声の聴感・OSごとの共有可能対象は別途確認が必要です。

backendは`internal/led/screen_test.go`、`adapters/screen_led_test.go`、`api/screen_led_test.go`でTTL境界、時計巻き戻り、偽ID・失効・再送、原子書込失敗時の前フレーム保持、待機のReset/ctxキャンセル、10fps上限、symlink拒否、HTTP入力制限、CSRF、毎frameの監査ログ非書込を検証しています。
