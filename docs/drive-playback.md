# ドラレコ再生

## 使い方と画面

録画ファイル名の一覧から探す代わりに、カレンダーで日付を選び、前方・車内それぞれの時間バーに示された録画区間をクリック/タップして再生する。選択した時刻に録画がなければ空白と表示し、近い録画へ勝手に移動しない。

PCはカレンダーと映像を並べる。スマートフォンは折りたたみカレンダー、録画開始時刻のチップ、映像、時間バーの順とし、並列映像は狭い画面では縦に配置する。初回は最初の録画を見つけやすい15分または1時間へ拡大する。15分/1時間/6時間/24時間へ切替でき、秒単位の時刻入力と前後の録画区間ボタンも使える。

再生速度は0.5/1/1.5/2倍。前方・車内のMP4原本をブラウザーのvideo要素へ渡し、音声トラックも変換せず再生する。並列表示は前方の音声を使い、前方に録画がないときは車内を使う。もう一方は初期状態でミュートする。並列のずれは再生中に0.6秒超で補正する。サンプル単位の同期や映像/音声の再エンコードは行わない。

実機の通常録画には、ファイル時刻とMP4長の関係により約1秒重なるものがある。重複時刻の指定は新しい開始時刻のファイルを使う。再生終端で次のファイルが連続/重複している場合は、重複部分を再生し直さず継続する。2秒を超える空白では自動的に次へ飛ばさず停止する。

## 索引と読み取り

- `DRIVERECDATA/Video`、`Event`、`Parking`の既知録画名を対象とする。`FILEM_YYMMDD_HHMMSS_...MP4`は前方、`FILEE_...`は車内。時刻はJSTとしてUTCへ変換して返す。
- MP4のbox境界、ftyp、確定moov、mvhdの有限duration、video sample descriptionを検証する。映像本体はdecodeせず、moovが末尾のMP4にも対応する。
- 更新直後のファイルは確定待ちとし、読み取り前後のsize/mtime変更を検出する。古い不正MP4も再生対象にしない。確定待ち件数は「書込み動作を確認した」という意味ではない。
- 日付集計の録画秒数は前方/車内の時間区間の和集合で計算し、両カメラを二重計上しない。日をまたぐ録画は両日へ分割して計上する。
- 15秒キャッシュ中もSDのmount identityを確認する。IDはmount identityと相対パスに対応し、SD交換後の古いIDは拒否する。親参照、絶対パス、symlink、既知ディレクトリ外は許可しない。
- 各既知フォルダを最大20000件まで索引化し、上限超過はUIに表示する。UIは選択した日だけのclipsを取得し、全日付のcalendar索引を併せて受け取る。
- stream/downloadは原本のままHTTP Rangeを使う。SDへの書込み、削除、移動、フォーマットはない。

APIの4経路とschemaは[api-openapi.yaml](api-openapi.yaml)に記載する。ブラウザーで扱えないcodecは原本ダウンロードで確認する。サムネイル、イベントの詳細分類、録画中MP4のライブH.264/AAC配信は未実装であり、ライブカメラのJPEG表示とは別機能である。

## 検証（2026-11-11）

Goの録画関連テスト6本とadaptersのgo vetが合格した。破損/未確定MP4、mvhd v0/v1、JST日跨ぎ、重複時間の和集合、SD交換時のID失効、既知ディレクトリ、親参照拒否、確定待ちを検証する。ローカルの非公開実機サンプルが存在する場合のみ、H.264/AACメタデータの実ファイル検証も行う。サンプル本体はGitへ含めない。

Playwrightの合成録画による操作試験5本が合格した。1440px/390px/320px、カレンダー、録画区間、空白時刻、タッチ、キーボード、並列のミュート分離、任意秒seek、重複境界の連続再生を確認した。レビューで改善した点は、最初の区間へ拡大、モバイルの開始時刻チップ、秒までの時刻表記、文字拡大、狭い画面での目盛り間引き、全録画から選択日だけの取得への変更である。

実機は合成fixtureを使わず、確定済み原本で以下が合格した。確認時は前方106本/車内106本、確定待ち2本、読取不能4本を検出した。

- H.264（avc1）1920×1080、AAC（mp4a）48kHz/2chのmetadata。
- 先頭/末尾のRange 206、Content-Rangeと実際の部分応答長。
- 指定時刻の7秒後からのseek、映像frameのdecode、再生時刻の前進。
- 車内の実frame decode、並列2本の実frame decodeと片側だけの音声出力設定。
- 約1秒重複する実際の次ファイルへの連続再生。

音声トラックの存在とブラウザー再生設定を確認した。実機スピーカーからの可聴音量を判定する試験ではない。実機映像・生の録画索引・画像はGitへ追加しない。

再実行例（UI dev serverは別途起動する）:

```powershell
powershell -File tools/create-playback-test-media.ps1
cd frontend
$env:NCC_UI_REVIEW_URL='http://127.0.0.1:5173'
npx playwright test tests/drive-playback.spec.ts
# 実機をHTTP 80へforwardした場合の読み取り専用検証
$env:NCC_BASE_URL='http://127.0.0.1'
$env:NCC_PLAYBACK_HARDWARE='1'
npx playwright test tests/playback-hardware.spec.ts
```

合成MP4生成はホスト側のFFmpeg（libx264またはh264_mf）だけを使う。実機のencoderやカメラ設定は変更しない。
