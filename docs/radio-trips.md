# 走行統計と電波マップ

## 取得元と欠測

走行統計は純正SD録画の `DRIVERECDATA/Video/FILE[ME]_*.NMEA` を読み取る。録画やGNSSサービスへの設定変更・セッション開始は行わない。チェックサム付きRMCの有効測位とUTC日時、同時刻GGAの品質・HDOPを検証する。GGAのHDOPをメートル精度へ換算しない。録画ファイル名の日時から、存在しないGPS日時や位置を補完しない。

2026-11-11の接続実機から、読取り専用で取得したsidecar 1ファイルを確認した。RMC 180件はすべてV、GGAは品質0、GPS日時・座標は空欄だった。この資料自体はGit管理外のtmpに保存した。有効測位のない現在の走行距離・時間は不明が正しい。録画時間を走行時間へ置き換えない。

同一時刻の前方・車内データは重複計上しない。有効な点同士でも5秒超の間隔、無効測位、HDOP 5超、既知精度50m超、75m/s超の移動は区切る。連続測位で静止を実測した区間は距離・走行時間0、欠測日はnullとする。速度0.5m/s以上の区間を走行時間として積算。日付はJST、日付境界をまたぐ短い区間は時間比で分ける。これは測位に基づく集計であり、車両の積算計やエンジン時間ではない。

## APIと保存

各sidecarの開始点は区切りとする。直前ファイル末尾にGPS日時のない無効測位があっても、次ファイルの測位へ直線で補間しないためである。

`adapters.TripStats(ctx)` は30秒キャッシュのSD読取インデックスを使い、periodsの7/30/90/365日別統計を返す。期間ごとのdistanceKm・drivingSecondsは欠測時null、daysにはobserved・sampleCount・observedSecondsを付ける。SD識別子はキャッシュ利用時にも再確認する。最大5000ファイル・各2MiB・サンプル合計100000件（cacheを含む）。上限をまたぐファイルでは新しい測位を残して切り詰め、大きなbacking arrayを解放する。切り詰めたcacheは後で余裕ができた際に再読取りする。上限到達はsourceTruncatedとしてDashboard/走行履歴に表示する。SD取り外し・交換はキャッシュ失効。`LatestGNSS(ctx,at)` は5秒以内だけ返し、過去のsidecarを現在の電波と結合しない。

`GET /trips?period=7|30|90|365|all|custom` は同じインデックスから日別集計と区間詳細を返す。旧 `?days=7` 等も受け付ける。customは `from=YYYY-MM-DD&to=YYYY-MM-DD`（JST、両端日含む）、日付不正・未来日・逆転・36600日以上・条件重複は400。allは有効な測位の取得範囲を使用し、測位がなければunknown。日跨ぎの実測区間は範囲に按分し、未来サンプルは使わない。最新1000区間を返し、超過時はdetailsTruncatedを付ける。集計に位置そのものは含めない。

`JourneyChart.vue` はDashboardと走行履歴の共通表示。7/30/90/365日・全期間・期間指定と日毎/週毎/月毎に対応する。距離と時間は2色のpaired棒、計測分の累計は同色の折れ線。左軸は各区間、右軸は累計で、それぞれ距離km/時間hの色別目盛りを併記する。累計を未計測日で0へ戻さず、欠測や一部欠測を含む集約区間で折れ線を切る。停止を実測した0と未計測nullを区別する。各区間をタップ、Enter/Space、左右/Home/Endキーで選択すると値と累計を表示。狭い画面は左右軸を固定したプロット内だけを横スクロールする。

`DriveHistory.vue` は共通グラフ、日付指定・記録のある日の選択、区間の開始/終了/距離/走行時間/測位時間、取得元の状態、電波マップを組み合わせる。日別集計と日跨ぎ区間全体の数値を区別し、未測位のファイルを0kmの走行として表示しない。

電波履歴の `radio.NewHistory(dir)` と `Query` 自体は保存を開始せず、常時ロガー側が `Append(Observation)` を実行する。ユーザーの指示により個別の保存許可は求めない。JSONL 16MiB×2世代、地図応答は直近20000件。位置・電波は同時刻差5秒以内のみ表示する。位置精度不明は既定除外で、利用者が選んだ場合に点・経路へ表示し、集計には含めない。回線・バンド・指標・期間で絞り込み可能。

グリッドは20/50/100m固定区画。走行IDが判明していれば走行ごとの中央値を等重みで集計し、不明なIDを日付などから捏造しない。ID未取得の観測が含まれる場合は全観測の中央値へ切り替え、走行数不明を表示する。圏外・未取得を弱電波の数値へ置き換えない。

背景地図はOpenStreetMapを既定ONで表示し、地図設定で任意OFFにできる。CSV/GeoJSONは表示対象の実観測のみ書き出す。

参照: ユーザー提供のradio-map（MIT、Copyright 2026 socho）。期間・指標・バンド・精度・経路/区画の考え方を参考に、NP1用に独立実装した。元のHR01向けAT/QRTR設定やrootfs変更は使用していない。

## 検証と自己レビュー

- Go単体テスト: RMCチェックサム/GGA、全欠測、静止0と欠測null、5秒超欠測と異常移動の切断、JST日跨ぎ、前後カメラ重複、履歴読取りの無副作用、時刻差・精度不明・圏外除外を合格。
- `go vet ./internal/trips ./internal/radio ./internal/adapters` 合格。
- frontend型検査・Viteビルド合格。
- Playwrightのradio専用8テストで1440/320px幅のlight/dark/system、実行中のOS配色切替、未測位理由表示、指標変更、背景地図既定ONと任意OFF、欠測時export無効、横はみ出しなしを合格。
- 選択欄・空表示・Leafletズームの実計算コントラスト比4.5以上、popupとattributionの配色追随を検証。スクリーンショットを目視レビューし、320pxで指標選択欄を全幅にし、選択肢の省略を改善。背景タイルのみダーク用フィルターを適用し、観測点の色は変更しない。
- 履歴のGoテスト: custom/allの境界、日跨ぎ按分、未来サンプル除外、既存Statsとの合計一致、no-fixと単独fixのnull、停止0、GET専用/不正条件拒否、座標非出力を合格。
- Playwrightのjourney専用9件: 1440/320px × light/dark/system、2色paired棒、累計の欠測切断、実測0、日週月・全期間・custom、キーボード選択、日別区間詳細、未測位の根拠、横はみ出しなしを合格。既存usabilityのグラフ関連2件も新仕様で合格。時間目盛り0.15hを0.2hへ丸めないよう2桁表示し、PCプロットが横幅を使い切るよう改善した。

実走行の有効測位が現在は得られていないため、実機の距離・走行時間の一致検証と走行経路描画は未完了。合成データによるテストを実測合格としない。
