# ネットワークとアクセス制御

Web UIにはパスワードを設けません。ホットスポットの認証とTailscaleのアクセス制御を境界とし、同じ管理ネットワークから到達できる端末は管理機能を利用できます。HTTPは80、HTTPSは443で提供します。インターネットへ直接ポートを公開する用途は想定していません。

HTTPSには本体で生成した自己署名証明書を使用します。`tools/connect.py` はADB経由で証明書を取得し、SHA-256指紋を表示します。証明書警告を避けて開きたい場合は管理ネットワーク内でHTTPを利用できます。

## APIの境界

Webプロセスは専用ユーザーで動作し、rootの任意コマンドを実行するAPIはありません。brokerはUnix socketの接続元を検査し、固定された操作と入力範囲だけを受け付けます。HTTP / HTTPSごとのCSRF cookie、Origin・Host検査、CSP、frame拒否などを適用します。

純正サービス操作には依存関係の制約があります。カメラを使うサービスを残したままQMMFを停止する操作など、本体に影響する組み合わせを拒否します。systemdのactiveだけで純正機能の動作完了とは扱いません。

OTA制御は、本体のファームウェア更新でNP1modが動かなくなることを防ぐため、次の仕組みを重ねます。ファームウェアの書き換え、純正サービスの停止・無効化、進行中アップデートの強制中断は行いません。

| 層 | 内容 |
| --- | --- |
| 取得の停止 | 純正の更新処理が更新リストの取得前に確認する停止フラグ（`/pio_data/SYSTEM/Update/no_ota_download`）を置きます |
| 削除防止 | フラグのあるフォルダーは誰でも書き込めるため、NCCが作ったフラグに変更不可属性を付け、純正の処理からも消せないようにします |
| 自動復旧 | 見張り役（`np1-control-ota-guard.service`）が30秒ごとに確認し、所有者が更新を許可していないのにフラグが消えていれば作り直します |
| 通信遮断 | 純正の更新処理は専用アカウントで動きます。そのアカウントの外部へのIPv4通信だけを、NCC専用のiptablesチェーンで拒否します。ほかのプロセスやループバック、D-Busは対象外です |
| 監視 | 取得済みの更新データ、更新リストに提供中の更新、SDカードの更新用ファイル（`update.Auth`）、更新処理のファイル変化を調べ、画面に警告します。監視は読み取りだけで、何も削除しません |

設定画面から更新を許可すると、フラグと通信遮断を解除します（非推奨、確認あり）。設定を読み取れない状態や未知のファームウェアでは、通信遮断を解除しません。この本体にはip6tablesがないため、IPv6の外部経路ができた場合は遮断できず、画面に警告します。

## 保存するデータ

走行ロガーは導入後に動作し、有効な位置と電波の観測を本体へ記録します。カメラ表示や位置記録のための独自の許可ダイアログは設けません。背景地図を有効にすると、表示範囲のタイル取得が外部サービスへ発生します。NAS転送は設定した保存先へ録画原本を送信します。

画面連動LEDと共有音声はブラウザー標準の画面共有機能を使います。共有対象の選択はブラウザー側で行い、受け取った色・音声は短期セッションで扱います。この機能で元の画面や音声を本体へ永続保存しません。

ナンバー認識を有効にすると、前方映像から読み取った他の車のナンバーと位置・時刻を本体に記録し、条件に合致したときは前方映像の1フレームを保存します。これらは本体の外へ送信しません。読み上げを使う場合、条件のメッセージ・定型文・番号まで指定した条件の読み・ナンバーを読むための部品（地名や数字など）を、設定したVOICEVOX APIへ送信します。検知した車のナンバーは送信しません。APIキーは本体に保存し、APIの応答や画面に表示しません。

NAS資格情報、Tailscale state、TLS秘密鍵、VOICEVOX APIキー、診断の生データは公開ソースに含めません。設定や診断を手動で共有する場合も、認証情報・端末識別子・位置・映像を含むファイルをそのままIssueへ添付しないでください。
