# 単一フレームの限定アンサンブル

追跡中に鮮明なフレームが1枚しか得られない場合でも、安全に確定できる一連番号を増やすための処理です。旧OCRを常時使用したり、旧OCR単独の結果を採用したりはしません。

## 判定の流れ

1. 通常は現行OCR、数値検証器、桁位置OCR、追跡系列の候補を使います。
2. 幅35〜64 pxの4桁候補で、現行OCRと数値検証器が競合した場合だけ `ocr-legacy.tflite` を追加実行します。
3. 独立した読取り系の一致、または1桁競合時の桁別多数決を満たした候補だけを採用します。
4. 単一フレームを即時確定する場合は、通常の複数フレーム確定より厳しいスコア条件を課します。条件を満たさない候補は従来どおり保留します。
5. 3桁表示は、複数フレームの完全一致と画面外へ向かう軌跡を同時に確認します。静止した誤読の繰返しは確定しません。

`legacyOcrMs` はエンジンのプロファイル情報に記録されます。旧OCRは競合時だけ実行されるため、通常フレームには追加推論コストが発生しません。追加モデルのファイル、SHA-256、評価条件は `models/plate/model-manifest.json` に記録します。

## 保存側の扱い

上記の厳しい条件を満たした狭い単一フレームには `InstantVerified` を付けます。保存層はこの印がある候補だけを1回の観測で確定でき、通常の狭い候補には引き続き複数観測を要求します。これにより、一般的な単一フレーム許可を行わずに取りこぼしだけを減らします。

固定182台の評価値と棄却した比較条件は、Git管理対象外の `docs_private/plate-tracking-single-frame-ensemble-20261127.md` に記録します。
