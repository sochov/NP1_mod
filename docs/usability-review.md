# 利用者視点の画面レビュー・改善記録

2026-11-11。ダッシュボードとLED操作を中心に、PC 1440px、スマートフォン390px、小画面320px、ライト・ダーク、データ未取得時と記録ありの場合を確認した。スクリーンショットは個体情報を含み得るため `tmp/` のみに保存。

## 判断基準

最初に知りたいのは「どれだけ走ったか・どれだけ通信したか」と「現在利用できる接続・録画・本体状態」。取得元パス、カーネル、ファイルシステム、内部サービスのactiveは主役にしない。未取得を0、未確認を正常、Tailscaleオンラインを遠隔Web疎通成功と表示しない。

## 発見と修正

| 利用時の問題 | 改善 |
| --- | --- |
| 緑寄りの面と小さい文字で操作・状態の優先順位が不明瞭 | 白・グレー／中立ダークの面、青い操作色。メニュー14px太字、44pxの領域。見出し・数値・補助情報を区別 |
| 同じ期間の距離・時間だと分かりにくい | 同一枠に距離と時間。7/30/90/365日切替。単位を混在させずグラフ指標を切替 |
| 365本の棒が切れ、記録欠落が0に見える | 7/30日は日別、90日は7日単位、365日は月別。全日付を補完し、未観測は欠測表示、観測済み0は点。部分観測は斜線。タップ・キーボードで日付、値、観測日数を表示 |
| 欠測nullでtoLocaleString/BigInt例外 | 数値・10進文字列を検証。欠測は「—」、CPU/RAM欠測も0%の棒にしない |
| 通信量が完全な履歴に見える | 「記録分」、記録開始日時、現在の集計回線、最終更新、更新停止を明示 |
| Tailscaleオンラインから遠隔利用可能と断定 | 管理ネットワーク接続、アドレス、直接/リレーの経路を分離 |
| LTE未登録・AP未取得が正常や停止に見える | true/false/unknownを区別。接続端末数0は実測値として残す |
| サービスactiveから録画中と誤認 | 書込み実測がなければ確認中、確定録画件数があれば保存済み件数 |
| SD85%以上警告が循環録画の平常運用を異常に見せる | 使用率のみの警告を廃止。空き容量・使用率を中立表示。書込み異常・停止の実測時だけ警告する方針 |
| モバイル2列カードが細くSSID・状態が折れ過ぎる | 520px以下1列、詳細はカード内2列。長SSIDを折返し横スクロールを防止。空グラフ132px |
| PC→モバイル撮影でサイドバーが重なる | 0.2秒transition途中の撮影だった。right<=0を待機し再撮影。メニュー開閉後も同条件・横幅を自動検証 |
| LED未取得でも仮初期設定で適用できる | 設定取得完了・利用可能まで編集と適用を無効。取得失敗時は状態更新を案内 |
| LED適用中の再操作と遅延loadによる編集上書き | 適用中は入力・更新・再適用を無効。ハンドラでも重複を拒否。遅延loadを廃止し応答を反映 |
| LED失敗後に古いrevisionで再試行できる | 失敗後は適用無効、状態更新から再開。競合理由を日本語化。成功は設定受理とし実点灯とは分離 |
| LED速度・読戻し・音声説明が実装用語中心 | 明るさ%、色の一周秒数、滑らかさ、端末の受理設定という一般語へ。ライブ音声未対応とドラレコ音声を区別 |

## 検証

`npx vue-tsc --noEmit` 合格。隔離ブラウザfixture `frontend/tests/usability.spec.ts` 4件合格。合成値はテスト内だけに置き、実機へ送信・保存していない。

1. 390px・距離時間/通信量null、LTE未登録、AP未取得、CPU/RAM欠測。
2. PC・記録あり、観測済み0、欠測、90/365日集約、ダーク、PC→390px・メニュー開閉後のサイドバー退避。
3. 320px・長SSID、64bitカウンタ、月次欠測、更新停止、30日表示。
4. LED取得失敗→更新、適用中二重操作抑止、revision競合→更新→再適用、390pxの操作。

全件pageerrorなし、横スクロールなし。スクリーンショットは `tmp/browser-results/`。

再実行（実機LEDを書き換えないブラウザ内fixture）:

```powershell
# 別プロセスで npm run dev -- --port 5174 を起動
cd frontend
$env:NCC_UI_REVIEW_URL='http://127.0.0.1:5174'
npx playwright test usability.spec.ts
```

実機APIをHTTP80からローカルViteへ読取りproxyした旧配備ダッシュボードもPC/390pxで例外・横スクロールなし。確認時backendはusage・走行統計・CPU/RAM容量未配備。その欠測を成功データとして数えない。最新backend配備後の画面・純正サービス確認は実機配備手順側で行う。

## 他画面へのレビュー連携

- Appの「簡易表示／詳細表示」は「詳細を表示／閉じる」を推奨。中央画面担当へ連絡済み。
- Tailscaleでも出るLOCALバッジ削除。中央画面担当へ連絡済み。
- カメラ許可画面廃止に合わせ、期限切れ「再度許可してください」を再表示案内へ変更。
- 「ドラレコ再生」に統一しカレンダー・横時間軸から探す導線を採用。別担当の実装。
- 今後有用なのは録画最終更新・書込み異常、測位最終成功時刻、通信履歴の欠落期間。未取得を正常と見せる表示は加えない。

## OTA設定の追加レビュー

OTA画面を320/390px・ライト/ダークの合成browser fixtureで確認。横方向のoverflow、sidebar重なり、console errorなし。未取得時の変更不可、適用中の二重送信禁止、競合エラー後の状態更新を検証し、5件合格。進行中の更新を中断しない説明と、再有効化が非推奨であることを同じカードに表示した。目視で後続カードとの間隔を改善した。APIの型/欠落/null/未知field/複数JSON拒否と、元のflag有無・内容の復元は別のGo testで確認。これらは合成fixture/host検証であり、実機OTAダウンロード試験を成功扱いにしたものではない。

## Alexa設定の追加レビュー

NP1 SERVICEにAlexa画面を追加。現在のON/OFFを純正応答で表示し、連携保護でON固定なら理由を同じ画面へ出して操作不可にする。アカウント認証や現在のBluetooth接続を推測表示しない。認識ON/OFFの選択を44px以上のタップ領域で設け、320/390px・light/darkと未取得・成功・409・fixedを合成fixture7件で検証、横overflow/consoleerrorなし。320pxの通常ON/fixed ONを目視確認した。実機helperの設定・復元・保存はroot担当が別途確認済みで、browser fixtureと混同しない。
