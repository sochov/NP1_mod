# 利用者視点の画面レビュー・改善記録

2026-11-11。ダッシュボードとLED操作を中心に、PC 1440px、スマートフォン390px、小画面320px、ライト・ダーク、データ未取得時と記録ありの場合を確認した。スクリーンショットは個体情報を含み得るため `tmp/` のみに保存。

## 判断基準

最初に知りたいのは「どれだけ走ったか・どれだけ通信したか」と「現在利用できる接続・録画・本体状態」。取得元パス、カーネル、ファイルシステム、内部サービスのactiveは主役にしない。未取得を0、未確認を正常、Tailscaleオンラインを遠隔Web疎通成功と表示しない。

## 検証

`npx vue-tsc --noEmit` 合格。隔離ブラウザfixture `frontend/tests/usability.spec.ts` 4件合格。合成値はテスト内だけに置き、実機へ送信・保存していない。

1. 390px・距離時間/通信量null、LTE未登録、AP未取得、CPU/RAM欠測。
2. PC・記録あり、観測済み0、欠測、90/365日集約、ダーク、PC→390px・メニュー開閉後のサイドバー退避。
3. 320px・長SSID、64bitカウンタ、月次欠測、更新停止、30日表示。
4. LED取得失敗→更新、適用中二重操作抑止、revision競合→更新→再適用、390pxの操作。

全件pageerrorなし、横スクロールなし。スクリーンショットは `tmp/browser-results/`。

再実行（実機LEDを書き換えないブラウザ内fixture）:

```powershell
# 別プロセスで npm run dev -- --port 5174 を起動
cd frontend
$env:NCC_UI_REVIEW_URL='http://127.0.0.1:5174'
npx playwright test usability.spec.ts
```

実機APIをHTTP80からローカルViteへ読取りproxyした旧配備ダッシュボードもPC/390pxで例外・横スクロールなし。確認時backendはusage・走行統計・CPU/RAM容量未配備。その欠測を成功データとして数えない。最新backend配備後の画面・純正サービス確認は実機配備手順側で行う。

## 他画面へのレビュー連携

- Appの「簡易表示／詳細表示」は「詳細を表示／閉じる」を推奨。中央画面担当へ連絡済み。
- Tailscaleでも出るLOCALバッジ削除。中央画面担当へ連絡済み。
- カメラ許可画面廃止に合わせ、期限切れ「再度許可してください」を再表示案内へ変更。
- 「ドラレコ再生」に統一しカレンダー・横時間軸から探す導線を採用。別担当の実装。
- 今後有用なのは録画最終更新・書込み異常、測位最終成功時刻、通信履歴の欠落期間。未取得を正常と見せる表示は加えない。

## OTA設定の追加レビュー

## 全画面の追加レビュー

合成APIを使い、メニューから到達する20画面を1440/390px・ライト/ダークの4条件で確認しました。80画像、pageerrorなし、横方向overflowなし、操作系API呼出し0件。証拠は`tmp/usability-audit-evidence/`と`tmp/usability-audit.log`です。Wi-Fi/APのNAT共有状態・名称は同画面担当が更新中のため、こちらでは同時編集していません。

現配備の実機UIはdashboard・4G・Tailscale・本体・LEDを1440/390pxで読取りレビューしました。ブラウザでGET以外のAPIを遮断し、POST/PUT/DELETEは0件でした。SD・native・APN・NATの変更やカメラ開始は行っていません。実機画像は`tmp/usability-device-readonly/`、結果は`tmp/usability-device-readonly.log`だけに保存しています。確認時点の4Gは回線登録と通信接続の未取得を分けており、GPS未測位を走行距離0にせず、SD使用率のみの警告もありませんでした。

追加で、TailscaleがRunningでも未接続のときに再認証を勧める表示、SDブラウザの古い「索引は開発中」という説明、純正設定の各画面で同じ確認方針を何度も説明する点、LEDの保存モードだけが他ブラウザの画面連動を隠す点を見つけました。認証が必要な状態だけ認証ボタンを表示し、日本語の接続状態と管理アドレスを主役に修正しました。SDの説明は録画の時間検索とファイル確認の使い分けへ変更し、バックアップは「表示設定のバックアップ」と対象を明示、反復する内部説明を短縮しました。

LEDはlastCommand.modeがscreenなら「画面連動」と表示し、行の名称を「取得時の表示設定」、編集欄を「通常の表示モード」として区別します。別のブラウザの連動中でも保存済みの通常モードを編集できることをGETだけで検証しました。全画面画像レビューで純正設定の先頭説明とモバイルのメニューが重なる問題も発見し、同コンポーネントだけに保護余白を設けて5画面×2テーマの非重なりを検証しました。
