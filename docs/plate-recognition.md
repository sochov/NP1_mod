# ナンバー認識と発話

前方カメラの映像からナンバーを読み取り、場所と一緒に記録します。条件に合ったナンバーは地図で目立たせ、画像を保存し、本体のスピーカーで読み上げます。DRIVE RECORDERの「ナンバー」画面と、システム › LED / 音声の「音声合成（VOICEVOX API）」で設定します。

**開発版の機能です。** 精度・対象・制限を理解したうえで利用してください。認識した他の車のナンバーは個人に結び付き得る情報です。保存や共有の扱いは各自の責任で判断してください。

## LED通知

「条件と設定」の各条件で「LED通知」を設定できます。単色は色・明るさと「点灯」「ゆっくり点滅」「流れる光」を選び、レインボーは色が連続して変わります。発話中と終了後2秒間光り、発話を使わない条件は2秒間光ります。「本体で試聴」でも同じLED通知が動作します。発話なしの条件は「LEDを試す」で確認できます。

通知が終わると消灯します。画面連動中はその映像の表示へ戻ります。LED通知の初期値は「なし」です。システムの前面LEDも一時点灯が既定で、「点灯」「消灯」で試せます。

## 仕組み

| 段階 | 内容 |
| --- | --- |
| 認識 | 認識サービス（`np1-control-plate.service`）が、純正の前方カメラ出力（1920×1080）を毎秒2フレーム読みます。検出器でナンバーの位置を探し、読取り器で地名・分類番号・ひらがな・一連番号を読みます。純正のImageRecogやカメラ設定は変更しません |
| 位置 | 純正のGNSS（NMEA）から検出時刻に最も近い位置を付けます。測位できない場合は「位置なし」として記録し、地図には表示しません |
| 記録 | 同じ一連番号を2回以上読めた車だけを記録します（初期値。1回だけの誤読を除くため）。30秒以内の読みは同じ車としてまとめ、地名などは信頼度で重み付けした多数決で決めます |
| 発話 | 条件を保存したときに、読み上げる文をWEB版VOICEVOX APIで音声にして本体に保存します。検知したら保存済みの音声をつなげて、本体のスピーカーで再生します |

認識はすべて本体内で行います。記録・画像・位置は本体（`/overlay/owner-apps/np1-control/state/plate/`）にだけ保存し、外部へ送信しません。

## 使い始める

1. ナンバー画面の「条件と設定」で「ナンバーの記録を有効にする」をオンにして保存します。初期状態ではオフで、オフの間は認識処理も停止しています。
2. 「状態」タブで認識プロセスが「認識中」になっていることを確認します。
3. 走行すると「記録」タブの一覧と地図に増えていきます。一覧と地図の点は連動し、片方を選ぶともう片方が強調されます。

## 条件

条件は100件まで登録できます。指定した項目がすべて一致したナンバーを「条件に合致」として扱います。空欄の項目は問いません。

| 項目 | 指定方法 |
| --- | --- |
| 地名 | 完全一致（例: 相模） |
| 分類番号 | 数字と英字、`*`は任意の1文字（例: `3**`） |
| ひらがな | 1文字（カタカナで入力してもひらがなとして扱います） |
| 番号 | 一連指定番号の数字、`*`は任意の1文字（例: `12**`） |

認識できなかった項目は条件を満たしません。たとえば地名を条件にすると、地名を読めなかった記録は合致しません。条件に合致した記録は、地図ではオレンジの大きな点で最前面に表示し、一覧では条件名を付けて強調します。「画像を保存する」をオンにすると、検出したときの前方映像を検出枠付きで保存します。

## 読み上げ

条件の「本体で発話する」をオンにすると、「メッセージ → 定型文 → ナンバー」の順に読み上げます。

> やりますねぇ！番号を検知しました。世田谷、はち、いち、ぜろ、さ、19、19。

- **メッセージ**: 条件ごとの文（60文字まで）。文字で入力するか、音声ファイル（mp3・wavなど、30秒以内）をアップロードします。音声ファイルはブラウザーで変換してから本体へ送ります。
- **定型文**: 全条件で共通（初期値「番号を検知しました。」）。
- **ナンバー**: 検知した読み。読めなかった項目は読みません。番号は2桁ずつ（25→にじゅうご、05→まるごー）、分類番号は1桁ずつ読みます。
- **声と音量**: 「条件と設定」の「発話」で選びます。初期値はずんだもん（あまあま）です。音量は読み上げの再生音量だけを変え、本体の音量設定は変えません。

条件を保存すると、その条件の音声を生成します。地名・ひらがな・数字などナンバーを読むための部品（約300個）は、声を選んだときに1回だけ生成します。生成中・完了・失敗は条件ごとに表示します。保存済みの条件は「この画面で聴く」でブラウザーから、「本体で試聴」で本体のスピーカーから確認できます。

番号まですべて指定した条件（`*`なし）は、ナンバーまで含めた全文を1つの音声として生成するため、より自然に読み上げます。それ以外は、メッセージと定型文の音声に部品の音声をつなげます。

1台につき読み上げるのは1回、最初に合致した発話条件の分だけです。記録の「発話済み」は、本体での再生が完了したときだけ付きます。VOICEVOX APIが未設定のときは「発話できず（未設定）」になります。

### VOICEVOX APIの設定

読み上げには [WEB版VOICEVOX API](https://voicevox.su-shiki.com/su-shikiapis/) のAPIキーが必要です。

1. [su-shiki.com/api](https://su-shiki.com/api/) でAPIキーを発行します。
2. システム › LED / 音声の「音声合成（VOICEVOX API）」にキーを入力して保存します。エンドポイントは初期値（`https://deprecatedapis.tts.quest`）のままで使えます。互換APIを使う場合だけ変更してください。
3. 「接続を確認」で残りポイントを確認できます。

キーは本体にだけ保存し、画面にもAPIの応答にも表示しません。APIへ送るのは、条件のメッセージ・定型文・番号まで指定した条件の読み・ナンバーを読むための部品だけです。走行中に検知した他の車のナンバーは送信しません。

APIには1日のポイント上限と、短時間の利用制限があります。部品の生成は約1.5秒間隔で行い、制限に当たると自動で待ってから再開します。生成した音声のクレジット（例: VOICEVOX:ずんだもん）は画面に表示します。生成した音声を本体の外で利用する場合は、[VOICEVOXと各キャラクターの利用規約](https://voicevox.hiroshiba.jp/term/) に従ってください。

## 精度と対象

評価には、本体とは別機種のドラレコ映像と、学習に使っていない写真を使いました。

| 項目 | 結果 |
| --- | --- |
| 検出（評価用ドラレコ映像、ROI内） | 78% |
| 一連番号（記録に使う信頼度0.6以上の読み） | 誤り0件（71件中） |
| 地名・分類番号・ひらがな | 値を出したときの正答率97〜100%。21〜34%は空欄 |
| 記録に残った車（2回検出の条件） | Lipla-jpが読めた車のうち約半数 |

- 対象にしやすいのは、前を走る車、信号待ちの車、駐車中の車、交差点でゆっくり動く車です。すれ違う対向車はほぼ読めません。
- 夜間・遠方・強い逆光、事業用（緑）ナンバーは苦手です。地名は相模で97%ですが、湘南・横浜などは空欄になりやすい傾向があります。
- 本体のカメラで撮影した映像での評価は未完了です。

## 設計の概要

- **2段構成**: 検出器（MobileNetV2＋FPN、int8）が前方映像の中央下寄りの範囲（ROI）からナンバーを探し、読取り器（float32）が元の解像度から切り出した画像を読みます。日本のナンバーは文字の配置が決まっているため、読取り器は地名・分類番号・ひらがな・一連番号を位置ごとに分類します。
- **誤った記録を避ける**: 地名・分類番号・ひらがなは確信度が低いと空欄にし、条件に一致させません。一連番号の確信度が低い読みは記録しません。同じ番号を2回以上読めた車だけを記録します。
- **本体の負荷**: 本体内蔵の推論ライブラリは古く現在のモデルを扱えないため、TensorFlow Liteを同梱した推論エンジンを使います。検出に約0.2秒、読取りにナンバー1枚あたり約0.02秒（2コア）かかるため、毎秒2フレームで処理します。
- **読み上げ**: 純正の発話機能は任意の文をクラウドで合成する方式で、他の車のナンバーが外部へ送られます。本体内でVOICEVOXを動かす方式は、合成に再生時間の約8倍かかりました。このため、条件の保存時にVOICEVOX APIで音声を作り、検知時は保存済みの音声を再生する方式にしています。

モデルの学習データ・精度の内訳・ライセンスは [モデルの説明](../models/plate/README.md)、学習と評価の手順は [開発・検証](development.md#ナンバー認識) を参照してください。

## 負荷と保存容量

認識サービスは、前方映像を毎秒2フレーム処理します。CPUは最大1.5コア相当、メモリは384MBまでに制限しています。1フレームの処理は約0.2秒です。計測では、純正の録画・映像処理・音声サービスは再起動せずに動作し続けました。

| 設定 | 初期値 |
| --- | --- |
| 記録の保存日数 | 365日 |
| 画像の保存容量 | 256MB（超えたら古い画像から削除） |
| 同じ車とみなす間隔 | 30秒 |
| 記録する信頼度の下限 | 0.6 |
| 記録に必要な検出回数 | 2回 |
