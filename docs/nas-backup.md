# 録画のNASバックアップ

システムの「録画バックアップ」に、常時録画・緊急録画それぞれの自動ON/OFF、転送経路、タイミング、保存先を配置する。Wi-Fi STAとTailscaleで、プロトコル・ホスト・ポート・パス・認証情報を独立保持する。転送経路を切り替えても他方の保存先を消さない。対応はSMB2/3、SFTP、WebDAV。SFTPはホスト鍵指紋を照合し、HTTPSは通常の証明書検証を行う。

自動転送は5秒ごとに確定録画を調べ、1件ずつ処理する。リアルタイムはファイル確定後、SSID指定はそのWi-Fi STAに接続中だけ転送する。緊急録画を先に選び、同種別内は新しい録画を優先する。FIFOでまもなく再利用される最古ファイルへ偏らず、リアルタイムの記録を先に保全する。位置や録画内容をサーバーへ別送する処理はない。設定は初期OFFで、指定NASの接続先だけを試験用に保存した。

## 転送と復旧

SDのカード識別・原本ファイル・確定MP4を再確認し、元のH.264/AACを再圧縮せず保存する。保存先は設定したフォルダー内に固定し、生成したファイル名だけを扱う。SDの削除操作は実装しない。

ローカル原本のSHA-256を計算し、所有権を確認できる途中ファイルだけを再開する。再開前にはNAS上のprefixを原本と照合し、転送後にNASから全体を読み戻す。検証後に同名上書きなしで確定し、確定先でも再照合する。画面には原本確認・途中データ照合・転送・照合・確定後照合を区別して進捗を表示する。WebDAVは検証したprefixがあっても条件付きの全体再送であり、offset転送再開とは表示しない。

通信は指定IFと送信元へbindし、Wi-Fi STAのSSID・接続ID・BSSID、IF識別・IP・経路等の変化を監視する。選んだ経路が失われたとき4G等へ黙って切り替えず、転送を中断する。TailscaleとSSID条件は併用可能で、指定Wi-Fiにいる間だけTailscale経由で送る構成にも対応する。

中断操作はその種別の自動再試行も一時停止する。「この録画から再開」または該当種別の設定保存で再開する。設定変更・接続確認・転送はcontrollerの所有ロックとrevisionで調整する。再起動で中断したジョブは中断済みとして表示し、設定がONなら再度キューへ入れる。NASの途中・確定ファイルやSD原本を盲目的に削除して復旧しない。

## 配備と保存

私有設定は `/overlay/owner-apps/np1-control/private/nas`（0700）、各JSONは0600。Web/APIへ認証情報を返さず、操作ログにも本文を保存しない。brokerの書込み範囲へこのフォルダーを追加し、IF固定socket用のCAP_NET_RAWを追加する。

既存導入では次の順に反映する。最初の手順は自作broker unitと専用フォルダーだけを準備し、サービスを操作しない。2つ目はWeb/brokerだけを更新し、他workerと純正サービスの同一性を照合する。

```powershell
python tools/deploy.py --serial SERIAL --action nas-backup-install
python tools/deploy.py --serial SERIAL --action web-worker-update
```

## 確認済みと残る試験

- host: 転送・中断/再開・競合・改変拒否・資格情報の非公開、SMB/SFTP/WebDAVのfixture転送。自動OFF、SSID不一致、緊急録画優先、共有インデックス不変、種別ごとの再開を検証。
- 画面: 320/390/1440px、ライト/ダーク、経路別draft保持、種別個別保存、中断・再開の8件。保存先入力を折りたたみ、進行中ジョブを上部へ移すレビュー改善を実施。
- 最新回帰: カメラ待機・共通切替・play完了待ち中の受信継続の6件と合わせた14件が正常終了まで合格。WindowsのローカルChromium終了待ちは別プロセスの検証用BrowserServerへ接続する方法で回避した。アプリの試験assertionは省略しない。
- 実機: 指定されたNASフォルダーへ約19MBの原本を転送・全体読戻し。約242MBでは実際に中断し、検証済み約1.4MBから再開して確定先の全体照合まで合格。純正26サービスの状態・PID/Invocationを維持。
- 実機: Tailscale上の指定サーバーの既存共有へも約19MBを保存し、確定先の全体読戻し照合まで合格。共有ルートも指定できる。既存ファイルを削除・上書きしない。
- 実機: SSID不一致でジョブが開始されないことと、試験後の自動OFF・設定復元を確認。
- 実機: 指定SSID一致で新しい常時録画を自動選択し、約103MBを転送・確定先まで全体照合。試験後は元の経路/タイミング/SSIDと自動OFFへ戻り、純正26サービスの同一性も維持。
- 継続中: 緊急録画の実データ、切断・再起動を伴う復旧。現在のSDに確定緊急録画がないため、実際の緊急録画転送を通常録画で代用しない。

Web/broker再起動の実機試験では、約237MBの途中ジョブをjournalから復元し、検証済みprefixから再開した。転送・途中先全体照合・rename後、確定先照合中に旧10分上限へ達したため成功扱いせず停止。1ジョブとtransportの上限を30分へ合わせて配備した。その後はユーザー指示でNAS試験を終了し、既存確定先の再照合は未実施。timeoutでもSDやNASのファイルを消さない。自動設定はOFFのまま維持する。

現時点では保存先フォルダー直下に原本名とSHA-256を含む生成名で保存する。編集可能な日付/カメラ階層、NMEA等の付随情報、帯域/通信量・時間帯等の追加ポリシーは今後の拡張。30分を超える低速回線での大きな録画の完走は別途検証する。

再現用の `tools/verify-nas-backup.py` は資格情報をignored JSONからのみ読み、証跡を新しいtmpフォルダーへ保存する。Web APIを通して設定、接続確認、1件転送、中断/再開、自動1件試験を実行できる。自動1件試験は、開始前のOFFへ戻して終了する。実機の保存先・認証情報・原本名や映像を公開資料へ転記しない。
